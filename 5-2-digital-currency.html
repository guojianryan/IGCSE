Digital currency and blockchain

Digital currency is any money that exists only in electronic form. Blockchain is one way to record those transactions: a time-stamped ledger that, once agreed, cannot be altered. Bitcoin is an example, not the definition.

5.2.1

Money with nothing to hold

A digital currency exists only in an electronic format. There is no paper note and no metal coin. It is kept in a digital wallet on a computer, a phone, or a secure server.

The exam line

  • It exists purely electronically.
  • It has no physical banknotes or coins.
  • A wallet stores and manages it.

Different risks from cash

  • A hacker, rather than a pickpocket.
  • A network failure can block a payment.
  • Lose the private key and the funds stay locked.
Exam watch

Do not write “digital currency means Bitcoin.” Bitcoin is one digital currency. The syllabus term covers any money that exists only electronically. Blockchain is the ledger used to track transactions, not another name for the currency.

5.2.2

A ledger that remembers the order

In the form the syllabus uses, a blockchain is a digital ledger: a time-stamped series of records that cannot be altered. Copies are kept across many computers. No single bank owns the ledger.

Digital ledger

A record of transactions, spread across the nodes in the network and kept in step.

Time-stamped

Each block records when it was validated, so the transactions stay in order.

Cannot be altered

Once the network has agreed a block, changing it breaks the chain and the other nodes can see that.

Background for 5.2.2

A hash and a digital signature

The next section uses both words. Neither one is encryption. A hash shows whether data has changed. A digital signature shows who authorised it.

Hashing

A hash is a short fingerprint of some data. The same data always produces the same fingerprint. Change one character and the fingerprint changes. The fingerprint has a fixed length, however long the message was.

You cannot rebuild the message from the fingerprint. The transaction itself can still be read. A hash is not a secret and it is not a smaller copy of the file. It only shows whether the data still matches.

A digital signature

A digital signature shows that this person authorised this message, and that the message is still the one they authorised. The wallet owner signs with a private key, which stays in the wallet. Everyone else checks that signature with the matching public key, which can be shared.

Topic 2.3 uses the same kind of key pair for encryption, the other way round: the public key hides a message and the private key reads it. A signature does not hide the payment. The nodes still need to read who is paying whom.

How a payment is signed

  1. The wallet hashes the transaction, such as “Alice pays Bob 2.5 coins”.
  2. The owner’s private key is applied to that fingerprint. The result is the signature.
  3. A node hashes the transaction it received and checks the signature with Alice’s public key.
  4. If the amount was edited afterwards, or if someone else signed it, the check fails and the payment is rejected.

How the chain uses a hash

Each block stores its own hash and the hash of the block before it. That stored fingerprint is the link. Change an agreed transaction and the block’s hash no longer matches, so every later link fails too.

The signature checks one payment. The block hash checks that the agreed history has not been rewritten.

Same payment, same fingerprint

Hash the same payment twice and both arrows arrive at 4951b1d8. Change the amount and the fingerprint changes to a380f610. Each fingerprint is eight characters. The arrow does not run backwards, so the sentence cannot be rebuilt. Type either sentence into the lab below and the same classroom fingerprint appears.

How a signature is checked

Alice hashes the readable payment, then her private key stays in the wallet and makes the signature. A node hashes the copy that arrived and checks it with Alice’s public key. Match means accept. Differ means reject. The buttons below use this same sentence.

5.2.2 continued

What one block holds

A block holds the transactions, a timestamp, its own hash, and the hash of the block before it. The previous hash is the link. A digital signature on a transaction shows who authorised that payment. The hash below is a classroom fingerprint of those fields, not a real blockchain hash.

What is stored

Block 2’s previous hash is 0e42f289, the same fingerprint as Block 1. That is the link. The signature sits inside the transaction. The block then stores that transaction with the time and the two hashes. These fingerprints match the chain below.

Inside the block

  • Transaction data, such as sender, recipient, amount and a digital signature.
  • The time the block was verified.
  • The current hash: a fingerprint of this block’s data.
  • The previous hash: the fingerprint of the block before this one.

Why the link matters

Change a past transaction and that block’s hash changes. Every later block was storing the old hash, so the chain from that point no longer matches. The network can tell the record was tampered with.

5.2.2 continued

Why the currency uses a blockchain

A digital coin is data, and data can be copied. The shared ledger is what stops the same coin being spent twice. No central bank keeps the only copy, so one failed computer does not wipe the record.

Double-spending

Hand over a paper note and you no longer have it. A file can be duplicated. Before a new payment is accepted, the ledger is checked to see whether that coin was already spent.

No single authority

There is no central bank or single server running this ledger. If one node is hacked or crashes, the other nodes still hold the agreed copy.

Try to spend a coin twice

The ledger already contains one payment. Ask for another and see which coin the network will accept.

    Question 1 2 marks

    State what is meant by a digital currency.

    1. A currency that exists only in an electronic or digital form.
    2. It has no physical form, such as paper banknotes or metal coins.

    Question 2 3 marks

    Describe the role and characteristics of a blockchain in tracking digital currency transactions.

    1. It acts as a digital ledger.
    2. It stores a chronological, time-stamped series of transactions.
    3. The records are immutable: once agreed, they cannot be altered.

    Question 3 2 marks

    Explain why timestamps are essential in a blockchain transaction record.

    1. A timestamp fixes the chronological order of the transactions.
    2. That order prevents double-spending and shows when ownership of the currency was transferred.
